# Project Herdr terminals through a dedicated WebSocket

Scoutr will project one existing Herdr terminal at a time through a dedicated, authenticated terminal WebSocket: raw binary terminal bytes plus JSON lifecycle/control messages. Each socket carries exactly one reset generation; pane/mode/reset changes replace the socket, and confirmed takeover is a new socket intent, so untagged binary frames cannot cross generations. Herdr remains the sole process, PTY, terminal-state, hierarchy, and writable-controller owner; Scoutr will not reconstruct a terminal from `pane.read`, create a second shell, or mix terminal traffic into the existing JSON-only `/ws` command/feed route. This keeps reconnect and persistence aligned with Herdr while giving terminal traffic its own ownership, authentication, latency, and backpressure contract.
