## Shared product constraints

All plans must preserve the design contract at
`android/app/src/main/java/dev/scoutr/app/ui/theme/DESIGN.md`. Read that source
for tokens, typography, status colors, motion, reduced-motion behavior, and the
always-dark Material 3 rules. Use `docs/terminal.md` for terminal ownership and
keep the Chat composer contract (Enter inserts a newline and never sends).

Plan-specific safety decisions remain here: Close is confirmation-gated, Delete
is irreversible, and Abort is recoverable and deliberately ungated.

## Verification boundary

A plan's feature-specific checks are evidence, not permission to bypass the
repository verification workflow. During implementation, run only cheap,
focused checks that answer the plan's current question. After implementation
and review fixes are complete, reach review-clean/code-frozen state, then run
one final runtime acceptance pass using `skills/scoutr-verification/SKILL.md`.
Do not run emulator, instrumentation, screenshot, or recording acceptance after
every implementation step.

For final runtime acceptance, follow `skills/scoutr-verification/SKILL.md`. That
skill owns device targeting, completion signals, and runtime evidence; use
`docs/dev-workflow.md` for emulator, deployment, and recovery recipes.
